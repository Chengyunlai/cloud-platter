## 短时 CPU / 内存样本

采用主进程累计 CPU 时间差除以采样时间计算 CPU%，RSS 由系统 ps 读取。每个样本约十秒，
当前一块内置 Retina 屏幕，期间系统仍有其他应用运行。样本不等于能耗验收，也不用于声称
某个百分比的性能提升。

| 场景 | 时间 | 主进程平均 CPU | 主进程 RSS 范围 |
| --- | --- | --- | --- |
| 正在播放、场景显示 | 10.16 秒 | 3.25% | 62.6–69.3 MiB |
| 暂停、场景显示 | 10.10 秒 | 1.68% | 79.5–81.0 MiB |
| 正在播放、场景隐藏 | 10.12 秒 | 2.67% | 76.8–112.9 MiB |

隐藏样本包含设置交互和封面更新；暂停样本包含状态切换。它们的起始状态、进程生命周期与
工作负载不一致，不能直接比较差值来宣称节能。未计入 supervisor、Perl、短时 JXA 子进程、
GPU 或电池消耗；无媒体空闲、长时间内存趋势和稳定播放 GPU 基线尚未采集。

控制器真实暂停发送约 67ms，恢复播放发送约 59ms；随后只读状态查询确认暂停 / 播放变化。
这是控制器调用证据，不能代替桌面点击、控件焦点和多屏交互的验收。

## 十分钟进程树观察

独立候选 App 持续运行 600.047 秒，使用 `scripts/sample-process-tree.py` 每 0.5 秒采样。单块内置 Retina 屏幕；期间用户与维护流程仍使用 Mac，另有构建与打包工作，没有将播放器和界面固定在同一状态。

- 主进程平均 CPU：6.606%；包含存活及已回收 helper 的进程树平均 CPU：9.520%（单个逻辑核心为 100%）。
- 主进程 RSS 起始 105.203 MiB，结束 88.391 MiB；进程树 RSS 采样峰值 148.438 MiB。
- 最多同时 5 个进程；本次没有观察到 CPU 累计值回落的采样点。

Mach tick 按本机 `mach_timebase_info` 换算；系统回收的子进程 CPU 继续计入累计值。进程枚举与读取不是原子操作，RSS 求和可能重复计入共享页，短时内存峰值可能漏采。此混合会话没有显示十分钟内的净 RSS 增长，但不能证明无内存泄漏、稳定状态能耗改善或长时间稳定；未测 GPU / 电池。#9 中四种固定状态与 60 分钟趋势仍待完成。匿名原始记录保留在本次维护工作区，不包含媒体、PID 或路径，不随 App 采集。

## 复测入口

```bash
make check
make package VERSION=0.1.0-preview.4
```

`make package` 会重建 dist；需要保留旧包时先备份。只在需要匿名设置截图时指定导出目录：

```bash
CLOUDPLATTER_REVIEW_OUTPUT=/path/to/review make test
```

普通测试不导出截图。测试和生命周期探针使用匿名状态或无媒体系统命令；本记录只包含版本、
状态与资源统计，不保存原始 helper 输出、曲名、艺人、封面或收听历史。
