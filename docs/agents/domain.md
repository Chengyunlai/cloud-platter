# 领域文档约定

CloudPlatter 使用单领域文档结构。

## 开始工作前

- 阅读仓库根目录的 `CONTEXT.md`，使用其中定义的术语和边界。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策。
- 如果术语尚未定义，先判断是否真的需要新概念；需要时更新 `CONTEXT.md`，不要在 Issue、代码和文档中创造多个同义词。
- 如果实现与现有 ADR 冲突，必须明确指出冲突并新增 ADR，不得静默覆盖既有决策。

## 文件结构

```text
/
├── CONTEXT.md
└── docs/
    ├── adr/
    └── agents/
```

- `CONTEXT.md`：产品边界、领域术语、核心状态和隐私不变量。
- `docs/adr/`：影响多个模块或长期维护的重要架构决策。
- `docs/agents/`：Issue、分诊和领域文档的自动化消费规则。
