# ADR-0005：通过独立桌面控制层发送用户主动播放命令

- 状态：已接受
- 日期：2026-08-06
- 修订：[ADR-0004](0004-isolated-mediaremote-adapter.md) 中“首版保持只读”的产品边界

## 背景

全屏桌面场景位于桌面图标下方并整体点击穿透；直接让它接收鼠标会遮断整个桌面的图标、框选和
右键菜单。现有 MediaRemote Adapter 已支持上一首、播放/暂停和下一首命令，但命令总是发送给
点击瞬间的系统 Now Playing 应用，不能只依据可能已经过期的界面状态假定目标仍是网易云音乐。

网易云音乐当前没有通过 MediaRemote 发布可用的喜欢状态和完整喜欢命令参数。通过辅助功能点击
网易云菜单会增加权限、脆弱性和账号写操作，与这轮三个基础播放按钮的可靠性目标不同。

## 决策

- 每块显示器建立一个只覆盖控制条的小型非激活 `NSPanel`。控制层位于桌面图标上方、普通应用
  窗口下方；原全屏场景继续点击穿透，只有三个按钮所在矩形接收鼠标。
- 三个按钮仅发送 MediaRemote 的上一首、播放/暂停和下一首命令，对应 Adapter `send 5`、
  `send 2`、`send 4`。
- 每次发送前通过同一隔离 Adapter 执行不含封面的即时快照。只有当前来源仍为
  `com.netease.163music` 且存在可展示媒体时才发送命令；来源变化、资源缺失、超时或非零退出
  都返回脱敏失败结果。
- 界面不乐观伪造播放状态；按钮图标继续以播放状态源的后续事件为准。命令执行期间禁止重复
  点击，失败反馈不得包含曲名、艺人、封面或底层进程输出。
- 本轮不实现喜欢、收藏、随机、循环、进度和音量控制，也不引入 Cookie、社区逆向 API、进程
  注入或默认辅助功能权限。

## 后果

CloudPlatter 不再是严格只读应用，但写操作被限制为用户明确点击触发的三种瞬时播放命令。每块
屏幕会新增一个小窗口和轻量 SwiftUI 控件；多显示器同步仍由同一规范化状态与控制器驱动。

MediaRemote 是未公开接口，系统升级后命令可能失效；按钮必须安全禁用或显示脱敏失败提示，
不能回退到模拟键盘或控制其他播放器。
