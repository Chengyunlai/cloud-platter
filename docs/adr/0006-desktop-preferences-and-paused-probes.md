# ADR-0006：保存桌面显示偏好并降低暂停复核频率

- 状态：已接受
- 日期：2026-10-13
- 修订：[ADR-0004](0004-isolated-mediaremote-adapter.md) 的暂停静默检测与轮询间隔；其他边界保持。

## 背景

事件流没有承诺周期性心跳，正常暂停也可能长期没有事件。原先把四秒静默都视为失效，
并让暂停与播放使用同一秒级查询间隔，会在无状态变化时反复创建查询进程。全屏场景还缺少
隐藏与屏幕选择，用户只能退出应用恢复自己的桌面。

## 决策

- 保留播放时四秒静默阈值；暂停改为十五秒。watchdog 每四秒检测一次，因此触发时间可能
  比阈值晚一个检测周期。静默只代表需要复核，不直接证明连接已失效。
- 暂停的备用快照与最近主流完全一致时，更新复核时间并停止连续轮询；后续继续低频复核，
  避免永远停留在已过期的暂停状态。复核失败仍清除过期状态。
- 主流已失败或复核发现状态变化时，备用查询的播放、暂停、空闲、失败间隔分别为
  1、5、2、4 秒；主流恢复时立即更新状态和取消正在进行的备用查询。
- 使用 UserDefaults 保存显示开关与禁用屏幕 UUID。新安装默认所有屏幕显示；已有偏好优先，
  断开的屏幕保留禁用选择，新接入的屏幕默认显示。UUID 不可取得时退回当前 display id。
- 隐藏和禁用屏幕同时收起场景 Panel 与播放控制 Panel，避免不可见按钮阻挡桌面。隐藏不暂停
  音乐，播放状态仍继续观察；场景原有可见性动画策略停止持续刷新。
- 设置采用可滚动内容，允许多个显示器选项；全部屏幕禁用时显示可恢复提示，不自动改写选择。

## 后果

- 播放事件流正常时恢复仍实时；若事件流持续失效，暂停转播放由备用查询发现时最多需要等待
  五秒间隔加本次查询时间。稳定暂停的静默复核可能需要十五到十九秒加查询时间。
- 本地新增数据仅为显示偏好，不包含媒体内容，不引入网络请求或系统敏感权限。
- UUID 持久性取决于系统与显示器标识；某些转接器变化可能产生新标识，需要重新选择屏幕。
- 真正的多屏热插拔、Spaces、Stage Manager、系统睡眠和 GPU 能耗仍需现场验收，偏好模型
  测试不能替代这些验证。

## 替代方案

- 暂停时完全停止复核：会在事件流已失效时永久保留旧状态。
- 保持每秒查询：恢复较快，但正常暂停无变化时也承担持续进程开销。
- 隐藏时销毁所有播放观察：会增加恢复等待，且与仅隐藏桌面的用户语义不一致。
